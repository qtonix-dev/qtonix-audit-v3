Linking Employee Gmail to the HRMS

A one-time Google setup you do as admin, plus how to add employees so they can link their personal Gmail without errors.

The big picture. The employee side is already automated — each employee links their Gmail with one click in My Profile → My Gmail → Connect Gmail. The only manual work is yours, once: setting up the Google app and (for personal Gmail) adding each person as a “test user.” Google requires this — no code can skip it.

1 Create the Google project & OAuth app

  1. Go to console.cloud.google.com and sign in with the company Google account that will own this app.
  2. Top bar → project dropdown → New Project. Name it e.g. Qtonix HRMS Mail → Create, then select it.
  3. Left menu → APIs & Services → Library. Search Gmail API → open it → Enable. (If you also want interview calendar sync later, enable Google Calendar API too.)

2 Configure the OAuth consent screen

  1. Left menu → APIs & Services → OAuth consent screen.
  2. User type: choose External → Create.
  3. Fill the basics: App name (Qtonix HRMS), User support email, Developer contact email. A logo is optional. Save and continue.
  4. Scopes step: you can leave this as-is — the app requests its scopes at sign-in. (For reference, it uses Gmail read/modify, Gmail send, and email address.) Save and continue.
  5. Leave the app in Testing publishing status for now (that’s what the test-user path in Step 4 relies on).
Why “Testing” is fine. Because employees use personal @gmail.com accounts and the app needs Gmail send/read (Google calls these “restricted” scopes), leaving the app in Testing + adding people as test users is the fastest working path. Publishing to “Production” for personal Gmail would trigger Google’s full verification + a paid annual security audit — not needed for a small team.

3 Create the OAuth Client ID & set the redirect URI

  1. Left menu → APIs & Services → Credentials → + Create Credentials → OAuth client ID.
  2. Application type: Web application. Name it Qtonix HRMS Web.
  3. Under Authorized redirect URIs, click + Add URI and paste exactly:
    https://YOUR-APP-URL/api/gmail/callback
    Replace YOUR-APP-URL with the HRMS server’s public address (the same value set as APP_URL). It must match character-for-character, including https:// and no trailing slash.
  4. Click Create. Google shows a Client ID and Client secret — copy both.
Common Qtonix URLs — use whichever the HRMS actually runs on:
• https://people.qtonix.com/api/gmail/callback
• https://qtonix-audit-production.up.railway.app/api/gmail/callback

4 Add employees as test users

This is the step that stops employees hitting the “app not verified / access blocked” error.

  1. Left menu → APIs & Services → OAuth consent screen.
  2. Scroll to Test users → + Add users.
  3. Enter each employee’s personal Gmail address (the one they’ll link), one per line → Save.
Limits to know: up to 100 test users total, and you must add each address here before that person clicks Connect. Anyone not on this list will be blocked by Google. As new employees join, add their Gmail here first.
Tip: Use the HRMS admin tracker (HR Admin → Gmail Links) to see who still needs to link, then add those addresses here and send them a reminder.

5 Save the credentials in the HRMS

  1. Open the Sales CRM as admin → Admin → API keys.
  2. Paste the Gmail Client ID and Gmail Client Secret from Step 3, and save.
  3. Make sure the server’s APP_URL environment variable is set to the same base URL you used in the redirect URI (this is set in Railway and needs a redeploy if changed).

Once these are saved, the HRMS shows “configured” and the Connect Gmail buttons become active.

6 Roll out to employees

  1. In the HRMS, go to HR Admin → Gmail Links to see every employee and whether they’ve linked ✓ Linked or not.
  2. Click Remind all pending (or send a per-person reminder). Each employee gets an HRMS notification.
  3. Employees who log in also see a banner prompting them to connect.
  4. The employee clicks My Profile → My Gmail → Connect Gmail, signs into their Gmail, approves, and they’re linked. The admin tracker turns green.

Troubleshooting

What the employee seesCause & fix
“Access blocked: this app hasn’t been verified” / access_deniedTheir Gmail isn’t in the Test users list. Add it (Step 4) and retry.
“Gmail isn’t set up yet”Client ID/Secret not saved in the CRM (Step 5).
Google rejects the sign-in / redirect mismatchThe redirect URI in Google doesn’t exactly match {APP_URL}/api/gmail/callback, or APP_URL isn’t set. Fix Step 3 / Step 5.
“Google did not return a refresh token”The account previously authorized the app. Have them remove access at myaccount.google.com/permissions, then link again.
Want zero friction later? Moving the team to Google Workspace on the company domain lets you approve this app internally for everyone at once — no test-user list, no 100-person cap, no verification. Worth considering as the team grows.
